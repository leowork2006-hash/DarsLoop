# Submission checklist

Checked 5 October 2026 against the supplied official Participant Guide (PDF positions 29-32), final portal/rubric screenshots, and current public terms. Muse's brief is a secondary checklist; conflicting claims do not override official requirements. The public guide fetch failed during this recheck; the previously supplied archived guide was used. Later portal notices have not been independently verified.

## Repository requirements

- Public GitHub URL; a private repository is not accepted.
- Complete application code and permitted runtime files, with dependencies and reproducible setup/run instructions.
- Idea, architecture, AI use, source/tool/data origins, licenses and material restrictions documented.
- No beneficiary data, secrets or personal build/research documents in the public release.
- Actual publication history only; do not reconstruct/backdate earlier commits. Confirm the starting-version/reused-work disclosure against real evidence before final submission.

README.md, JUDGE_GUIDE.md, ARCHITECTURE.md, DEPLOYMENT.md, SOURCES.md, THIRD_PARTY_NOTICES.md, LICENSE, .env.example and package-lock.json serve these requirements. These filenames are our packaging choices, not an assertion that the organizer mandates every exact filename.

## Final judging rubric supplied in the dashboard

| Criterion | Weight | Evidence to show |
| --- | ---: | --- |
| Technical solution and AI use | 25% | Fresh permitted upload, real transcript/generation, working practice and architecture |
| Reliability and scholarly safety | 15% | Captured quotes/times, uncertainty handling, refusal/referral and ownership tests |
| Innovation and added value | 15% | Teacher-specific terms, audio-linked catch-up and class-grounded practice compared with generic note takers |
| Beneficiary experience, communication and accessibility | 10% | Simple capture/revision flow, phone layouts, readable language and honest guide scope |
| Benefit against the track success criterion | 20% | Appropriate learning progression and actual comprehension/task-success evidence; do not invent student outcomes |
| Operational realism and continuation | 10% | Durable jobs/storage, quotas, restart/retry, maintenance and explicit limitations |
| Presentation clarity and verifiability | 5% | Clear deck/video, accessible live URL and reproducible public source |

Features alone do not establish a score. Local/runtime checks are not beneficiary pilots.

## Other required submission materials

- Project name, description and accepted challenge path.
- One presentation file in the observed final form: PDF/PPT/PPTX, maximum 10 MB. Cover the problem, solution, mechanism, value, technology and actual screenshots. Ten slides is our planning choice, not a verified official slide-count rule. Recheck any later portal notice before submission.
- Explanatory video link, no longer than two minutes; judges must be able to view it.
- Working live product URL and public GitHub URL.
- Submit through the official portal and retain confirmation. This repository does not itself submit the entry.

Published deadline in the supplied guide: 6 October 2026, 23:59 Riyadh / 7 October 2026, 01:59 Pakistan. Check any actual later organizer notice; do not assume an extension.
